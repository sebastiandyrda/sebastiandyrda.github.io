# dyrda.info — working notes for Claude

Personal academic site for Sebastian Dyrda, Associate Professor of Economics,
University of Toronto. Rebuilt in 2026 from a 2014 PHP site into a Quarto static
site. Read this before changing anything.

## What this is

- **Quarto** static site. Source is `.qmd` + one hand-written stylesheet. No
  framework, no build tooling beyond Quarto, no JavaScript except a small BibTeX
  modal. There is no component library — the whole design is ~470 lines of CSS in
  `assets/styles.css`.
- Deploys from `main` via GitHub Actions to GitHub Pages, live within 1–3 minutes
  of a push. **A push to `main` publishes to the public site.**
- `dyrda.info` is a working academic profile. PDFs under `/files/` are cited in
  published papers, so a broken intermediate state is visible to colleagues and
  referees. Work on a branch and let Sebastian see it before it goes live.

## Never edit these

| Path | Why |
|---|---|
| `_site/` | Build output. Wiped and regenerated by `quarto render`. |
| `_generated/` | Written by `_scripts/build_pubs.py` on every render. |
| `_legacy/` | Frozen copy of the old PHP site, kept for reference only. |

**`publications.bib` is the single source of truth** for every publication and
discussion listed on the site. `_scripts/build_pubs.py` turns it into the Research
and Discussions listings plus the copyable BibTeX payloads. To change what a paper
shows, edit the `.bib` entry — never the generated markdown or HTML.

In that file, standard BibTeX fields are what visitors copy; `site*`-prefixed
fields (`sitecategory`, `siteorder`, `siteauthors`, `sitejournal`, `siteinfo`,
`sitenote`, `sitelinks`) drive display only and are stripped from the popup.

`_scripts/check_cv.py` compares the `.bib` against Sebastian's LaTeX CV and reports
drift without rewriting anything. Run it after touching `publications.bib`.

## Load-bearing CSS that looks like a mistake

Every one of these has a comment in `assets/styles.css` explaining it. They look
like errors or redundancy and they are not. Do not "tidy" them.

1. **`overflow-x: clip` on `html, body`** — not a typo for `hidden`. `hidden`
   makes html/body a scroll container, which silently kills `position: sticky` on
   the nav. The rule still applies, nothing sticks, and nothing errors.

2. **`.sitenav` negative margin + matching positive padding** — the nav sits
   inside the panel's side padding. Without the bleed, content scrolls through the
   gutters either side of the pinned bar. The `--pad` variable exists so the bleed
   tracks the panel at every breakpoint; keep them in sync.

3. **`--wordmark-size` redefined per breakpoint** — cannot be collapsed into one
   `clamp()`. The lockup measures ~10.15× its font-size, and the ceiling at any
   width is (panel content − 2rem gap − U of T mark). The mark resizes at
   breakpoints too. Exceed the ceiling and it wraps to a second line, because
   `.masthead` has `flex-wrap: wrap`.

4. **`.wordmark-name` does not lead with Roboto**, unlike `body` — deliberate.
   Only Roboto Regular/Medium/Bold are commonly installed, so naming Roboto first
   renders `font-weight: 300` as regular weight. The stack leads with
   `-apple-system` etc., which ship a true Light.

5. **`.page-title-hidden h1.title`** — not dead code. It hides the redundant
   "Research" heading visually while keeping the `h1` for screen readers and search
   results; the `.section-head` h2s nest under it. Applied via `body-classes` in
   `research/index.qmd`, and only there — Discussions and CV have no section head
   to stand in for a title, so theirs stay visible.

## The wordmark

Live HTML text, not an image. It replaced a 2014 bitmap (`gfx/logo_new.gif`,
still in the repo only because `_legacy/` references it). Proportions were measured
from that bitmap so it reads as the same mark: red bar `.58em` wide × `1.55em`
tall, `.62em` clear of the letters, ink `#4a505c`.

Desktop size is `3.5rem`. It was briefly `4.25rem` and Sebastian's verdict was
"too large, dominates the logo" — the U of T mark is the reference, so the wordmark
must stay visibly secondary. Judge any change by rendering candidate sizes side by
side against that mark, not by maximising what fits.

## House style

- Navy `#1e3765` headings, red `#c52424` accents, white panel on a light grey
  field. Carried over from the 2014 site; keep it.
- **No photographs of Sebastian anywhere.**
- Working Papers listed before Journal Articles. Discussion authors by surname
  only. Numbering restarts per section.
- Link pills are spelled out in full — "Replication Package", "NBER Working
  Paper", "VoxEU Summary". No abbreviations.
- Publication link order: versions of the paper first, then slides, then extras.

## Verifying a change

```bash
quarto render
cd _site && python3 -m http.server 8912
```

**Look at the result.** Screenshot the page and inspect it — do not conclude a
visual change worked by reading the DOM or the CSS. That has produced confident
wrong answers here more than once.

Two traps when capturing screenshots:

- Chrome headless does not reliably apply `--window-size` to the layout viewport
  at narrow widths; it clamps and crops, so phone media queries never fire and the
  crop looks exactly like a horizontal-overflow bug. Load the page in an **iframe
  of the target width** instead — an iframe establishes its own viewport.
- Browser cache is the single most common cause of "the change didn't work".
  Hard-reload, or verify with `curl` against the served URL.

## Hosting

GitHub Pages serves the site; the `CNAME` file (listed in `_quarto.yml` resources
so it survives every render) sets the custom domain. Email for `dyrda.info` stays
with the original Polish host — **never touch the MX, TXT/SPF or NS records**, only
the A records. Sebastian does not control DNS himself; changes go through the
hosting company.

If a deploy goes red but the build step passed, it is usually
`actions/deploy-pages` timing out in GitHub's queue. Re-run the job; do not debug
the repo.
